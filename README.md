# LoL 실전 퀴즈

https://jeongdoheun-source.github.io/lol-quiz/

정적 웹사이트입니다. 서버, 빌드, AI API를 쓰지 않습니다.
**모든 수치는 실행할 때 Data Dragon과 CommunityDragon JSON에서 읽습니다.** 코드에는 게임 수치를 하나도 적어 두지 않았습니다.

## 파일
| 파일 | 역할 |
|---|---|
| `js/core.js` | 데이터 로드, 두 소스 병합, 패치 변경 감지, 자동 갱신 |
| `js/questions.js` | 문제 생성기 59종(평타 처치·유효 체력 4종 삭제, 추천 빌드 4종 추가) (난이도 5단계 × 분야 6개) |
| `js/app.js` | 화면 |

## 난이도 (모두 5지선다)
| 단계 | 대상 | 예시 |
|---|---|---|
| 1단계 | 아이언~브론즈 | 소환사 주문 쿨타임, 기본 아이템 가격, 룬 빌드 분류, 사거리 구간, 스킬 키 |
| 2단계 | 실버~골드 | 사거리·이속 맞대결, 궁극기 쿨타임, 재료·상위 아이템, 핵심 룬, 룬 조합 규칙, 스펠 복귀 시각 |
| 3단계 | 플래티넘~에메랄드 | 1레벨 평타 처치 수, 마나 운용(스킬 몇 번), 스킬 사거리 vs 평타 사거리, 조합 비용, 스펠 남은 시간 |
| 4단계 | 다이아~마스터 | 레벨 N 스탯, 방어력 피해 감소율, 레벨업 공격 속도, 궁 타이밍 차이, 실제 아이템 스킬 가속 쿨타임, 아이템 산 뒤 평타 처치 수 |
| 5단계 | 그랜드마스터~챌린저 | 레벨 역전, 유효 체력 비교, 아이템별 유효 체력 증가량, 10분간 궁 횟수, 골드 효율 |

해설은 실제 값을 대입한 계산 과정을 단계별로 보여 주고, 흔한 계산 실수와 실전에서의 의미도 함께 설명합니다.
코드에 있는 것은 공식뿐입니다(레벨 성장, 스킬 가속, 방어력 피해 감소). 계산에 쓰는 수치는 모두 JSON에서 가져오고, 해설에 계산 과정과 공식을 함께 보여 줍니다.
골드 효율은 기본 아이템(롱소드 등)으로 능력치 1당 가격을 구하고, 고유 효과가 없는 아이템으로 나머지 능력치 가치를 역산해서 계산합니다.

## 데이터 소스와 상호 보강
**스킬 수치(쿨타임·마나·사거리) 우선순위:** CommunityDragon 게임 데이터 `game/data/characters/{챔피언}/{챔피언}.bin.json` → CD `champions/{key}.json` → DD
- Data Dragon의 스킬 수치는 실제 게임과 다르게 남아 있는 경우가 많아서, 게임 파일에서 직접 뽑은 값을 씁니다.
- 배열 규칙: `cooldownTime`·`castRange`는 1번 칸부터, `mana`는 0번 칸부터가 스킬 1레벨 값입니다.
- 충전형 스킬(`mMaxAmmo`, `mAmmoRechargeTime`)은 쿨타임 문제에서 뺍니다.
- DD 값과 달라서 바로잡은 경우에는 해설에 "Data Dragon에는 ○○초로 적혀 있지만 실제 게임 데이터 값을 썼어요"라고 표시합니다.

- **챔피언:** DD `champion.json`, `champion/{id}.json` ↔ CD `champion-summary.json`, `champions/{key}.json`
- **아이템:** DD `item.json` ↔ CD `items.json` (이름·가격·하위/상위·설명 중 빈 항목을 서로 채움)
- **소환사 주문:** DD `summoner.json` ↔ CD `summoner-spells.json`
- **룬:** DD `runesReforged.json` ↔ CD `perks.json`, `perkstyles.json`
- 어느 소스에서 채웠는지는 설정 화면과 문제 해설의 출처 배지에서 볼 수 있습니다.

## 자동 갱신
1. 문제는 저장하지 않고, 매번 지금 데이터로 즉석에서 만듭니다.
2. 5분~3시간 간격(기본 30분)으로 `versions.json`과 CD `content-metadata.json`을 확인합니다. 탭으로 돌아오거나 네트워크가 다시 연결되면 즉시 확인합니다.
3. 새 버전이 나오면 챔피언 스탯, 스킬 쿨타임·마나·이름, 아이템 가격·능력치, 소환사 주문 쿨타임을 이전 기록과 비교합니다.
4. 풀고 있던 문제가 쓴 값이 바뀌었으면 그 문제를 즉시 새 문제로 바꿉니다.
5. 바뀐 항목으로 "패치 변경" 문제를 자동으로 만듭니다.

## 스킬 피해 문제 (4단계)
- 값은 게임 데이터의 `DataValues`(레벨별 값, `mValues[1]`이 1레벨)와 `mSpellCalculations`(계산식)에서만 읽습니다.
- 지원하는 계산식: 숫자, 데이터 값, 능력치×계수, 합, 곱(한쪽이 상수일 때), 다른 계산식에 배수 적용. 그 밖의 형태(체력 비례, 레벨 구간 등)는 계산식 전체를 버리고 문제를 만들지 않습니다.
- 능력치 번호 해석(`mStat` 없음/0 = 주문력, 2 = 공격력, `mStatFormula` 0/1/2 = 총/기본/추가)은 공개된 bin 관례를 따른 가정입니다. 실제 데이터와 다르면 `js/core.js`의 `STAT_AP`, `STAT_AD`, `FORM_*` 상수만 고치면 됩니다.
- 피해 항목이 여러 개인 스킬은 문제에 "총 N개 중 M번째 피해 항목 「항목명」"과 시전 단계·구역을 표시합니다. 항목 이름에서 읽을 수 있을 때(First/Second, SweetSpot, Edge 등)만 단계·구역 문구를 붙입니다.
- 설정 화면의 「스킬 피해 계산식 구조 보기」는 아트록스·조이·아리의 계산식 원본을 보여 줍니다. 구조가 다르게 나오면 이 내용을 보내 주세요.
- 거리 비례 피해(조이 Q 등)는 아직 문제로 만들지 않았습니다. 실제 데이터 구조를 확인한 뒤 추가합니다.

## 추천 아이템 빌드 × 스킬 가속
- 추천 아이템은 CommunityDragon 챔피언 JSON의 `recommendedItemDefaults` → Data Dragon 챔피언 JSON의 `recommended`(소환사의 협곡) → 게임 데이터(bin)의 recommend 관련 항목 순서로 아이템 번호를 모읍니다.
- 세 곳 모두 비어 있으면 역할군(마법사 → 주문력, 탱커·서포터 → 체력·방어, 나머지 → 공격력)에 맞는 스킬 가속 전설 아이템으로 대신 빌드를 짜고, 해설에 그렇게 고른 사실을 적습니다.
- 추천 아이템의 하위 재료(여러 단계)도 따라가서 빛나는 티끌·점화석처럼 스킬 가속을 주는 재료가 있으면 빌드에 넣습니다.
- 문제: 완성 빌드 쿨타임, 완성템 + 다음 추천템 재료 쿨타임, 인벤토리 스킬 가속 합계, 쿨타임이 가장 짧은 빌드 고르기.
